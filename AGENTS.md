# Следующим агентам

Сначала прочитайте PROJECT_STATE.md и HANDOFF.md. История чата не требуется. Назначение: локальное инженерное исследование строительных конструкций, первая специализация — пассажирские платформы. Точность и происхождение важнее фотореализма.

## Структура

- src/model.ts — схема, генератор, количества, CSV.
- src/store.ts — Project отдельно от временного состояния.
- src/Viewer.tsx — R3F, камеры, выбор, замеры и разрез.
- src/App.tsx / style.css — UI, инспектор, ведомость, темы.
- src/importers.ts — чертежи, не реконструкция.
- src/export.ts — GLB и скачивание.
- src/model.test.ts / e2e — проверки; .github/workflows/ci.yml — CI.

## Правила

1. Временные положения не мутируют проектные координаты и количества.
2. Метры, Y вверх; преобразования CAD/IFC явные на границе.
3. Не считать сложные тела по габаритам. V1 — объединения AABB; V2 добавляет простые экструзии, замкнутые ориентированные тела и стержневые схемы. Схемы/огибающие не входят в quantities.
4. Не выдумывать неизвестные параметры; демо всегда условное, assumed.
5. Импорт, реконструкция и viewer — отдельные модули. Заглушка не означает поддержку формата.
6. Несовместимые изменения JSON требуют версии/миграции/тестов.
7. Обычный запуск без Docker/Blender/платных API. Python/IfcOpenShell добавлять опционально при реальном импорте.

## Код и проверки

TypeScript strict, React function components, без any, Prettier, русские понятные пользовательские тексты. Ядро не зависит от UI/renderer.

Запуск: Node 24 LTS, npm ci, npm run dev; Windows ./start.ps1.
Перед завершением: npm run typecheck, npm run lint, npm test, npm run build, npm run e2e. Для E2E предварительно npx playwright install chromium. Осматривать скриншоты при изменениях UI. Фиксировать фактические результаты, незапущенные тесты не считать успешными.

## Git и передача

Только csnicallyou/buildscope, всегда PRIVATE. Не менять видимость и другие репозитории. Сначала git status, учитывать чужие изменения. Крупные функции — отдельная ветка, регулярные коммиты/push. Без force push и разрушительного reset.

Не коммитить секреты, исходные строительные чертежи, node_modules/dist/отчёты. Синтетические тестовые DXF допустимы.

После этапов обновлять PROJECT_STATE: стадия, последний рабочий коммит, функции, ограничения, проверки, решения, ветки, следующие задачи. HANDOFF: что читать/менять/запускать. Указывать последний известный checkpoint; хеш собственного коммита внутри самого себя не записывать. Перед завершением отправить важные результаты в GitHub.
