# Панель управления стройкой 0.12

Главный экран общего сервера — «Обзор стройки»: дневная/ночная смены на выбранную дату, наряды на приёмку, просроченные задачи, препятствия и открытые замечания. Цифры получаются из сохранённых записей, а не из демонстрационных данных. Дата наряда — начало смены. На компьютере используется постоянная боковая навигация; на телефоне разделы открываются кнопкой «Разделы», основные действия доступны снизу. Светлая и тёмная темы сохраняются. Обычный локальный запуск с параметрами assembly/demo по-прежнему сразу открывает инженерный просмотр.

## Начало работы

1. В «Объекты и участки» создайте стройку и вложенные объекты. Кнопка «Создать структуру по доступным моделям КЖ» добавляет только известные стройку/павильон/навес; участки, оси, конструкции и части нужно уточнить самостоятельно. Иерархия не меняет проектные координаты.
2. В «Бригады» укажите название, бригадира и состав. Эти данные не создают автоматически аккаунты: доступ настраивается отдельно в «Команда и доступ». Название бригады в аккаунте, задаче и наряде должно совпадать.
3. Добавьте задачи: участок, даты, дневная/ночная смена, бригада, ответственный, предшествующие работы. Циклические зависимости запрещены. До завершения предшественников и закрытия критических замечаний запуск и выдача связанного наряда блокируются сервером. Статус задачи — ручная отметка работы; он не подменяет сдачу/приёмку наряда и не меняет расчётные количества.
4. Из задачи нажмите «Выдать наряд по задаче». В существующем редакторе выберите конструкции и операции, проверьте план. Сервер проверяет участок, бригаду, дату, смену и модельную привязку. Можно также выдать самостоятельный наряд. Перенос в другую смену создаёт черновик без старой taskId, чтобы не выдавать ночную работу по дневной задаче.

## Материалы

Регистрируются начальный остаток, поступление и расход: материал/марка, участок, единица, дата, бригада и основание (накладная, замер, запись расхода). Остаток по зарегистрированным операциям вычисляется отдельно для каждого материала, участка и единицы; массы и объёмы не конвертируются без основания. Отрицательный остаток запрещён. При попытке отменить поступление уже израсходованного материала сначала нужно исправить соответствующие расходные операции. Изменения и отмены сохраняются в истории.

Это учёт записанных операций, а не автоматически установленный физический запас на площадке. Фильтры бригады/участка и права определяют видимые операции. Потребность модели открывается отдельной кнопкой «Потребность по 3D-модели», сохраняя её статусы и происхождение. Сдача наряда не списывает материалы автоматически. Цен и финансового учёта нет.

## Качество и документы

Замечание содержит ответственного, срок, участок/конструкцию, важность и описание. Бригадир своей бригады отмечает устранение и вводит подтверждение; руководитель закрывает замечание после проверки. Закрытую запись может вернуть только руководитель. Критическое незакрытое замечание блокирует связанные задачи по участку/модельной привязке. Фото и комментарии прикладываются к связанной конструкции существующим механизмом ObjectNotes; текст подтверждения не означает автоматически подписанный акт.

Карточка документа хранит номер, редакцию, вид, дату, участок и бригаду доступа. Файлы PDF/XLSX/DOCX/DXF/JPEG/PNG до 25 МБ доступны через защищённый download, не через публичную статику. Для файла сохраняется SHA256. Заменить содержимое существующей редакции нельзя: нужно создать новую с ссылкой «Заменяет редакцию». Цепочка сохраняет прежние файлы; циклы и две замены одной редакции запрещены. Номер, участок и права бригады в цепочке должны совпадать. Карточку можно сохранить до загрузки файла, интерфейс явно покажет, что файла ещё нет.

Выбор конструкции в 3D показывает связанные рабочие записи. Из свойств можно создать задачу, замечание или документ с исходной привязкой, затем вернуться к модели и открыть сохранённую карточку. Пользовательские модели не загружаются на сервер автоматически; для неизвестной модели сначала нужно открыть исходный Project JSON. Генерация полной исполнительной документации и юридическое подписание актов не реализованы.

## Хранение и доступ

`construction.ts` — схемы и чистые вычисления; `construction-store.ts` — серверные ограничения и история; `ConstructionPanel`/`ConstructionObjectContext` — интерфейс. Project JSON v1/v2 не менялся. Наряд получил optional nodeId/taskId, прежние записи совместимы.

SQLite server schema v2 добавляет construction_records, construction_events и construction_files. Миграция с v1 не удаляет/не переписывает пользователей, наряды, факты, фотографии или существующие события. Каждое сохранение проверяет роль/бригаду и ревизию; устаревшая форма получает 409 и сохраняет свои поля до явной загрузки актуальной версии. Руководитель создаёт и планирует, бригадир меняет выполнение собственных задач/устранение замечаний, наблюдатель читает. Структура объектов общая; правила ограничения моделей пока прежние.

Все новые таблицы/файлы автоматически попадают в согласованные SQLite backups. Конфиденциальные документы, базы и реквизиты не добавляются в Git. Сервер не создаёт фиктивных работников, объёмов и завершённых работ.

## Обновление ВМ

`deploy/upgrade.sh` обновляет существующую установку, не выполняя bootstrap и не меняя Caddy/VPN. Перед переключением делает согласованный backup и проверяет миграцию новой версией на отдельной закрытой копии. Затем останавливает сервис на время миграции основной БД, сверяет число пользователей/нарядов и запускает новую сборку. Пути сервиса резервирования обновляются вместе с приложением. База остаётся /var/lib/buildscope/workspace.sqlite.

Версия 0.11 не умеет открывать server schema v2. Не переключать старый исполняемый файл на новую рабочую БД вслепую и не восстанавливать старый snapshot поверх записей пользователей. Для аварийного восстановления использовать инструкцию SHARED_WORKSPACE и отдельное решение пользователя о потере изменений после снимка. Сохранённые копии unit-файлов и preflight находятся в /var/backups/buildscope-before-<release>.

Ограничения первого выпуска: одно серверное рабочее пространство, календарь списком по датам/сменам (без оптимизации графика), состав бригад текстовый, склад без интеграции с поставщиками/весами, редакции документов без сравнения геометрии чертежей. Новые формы сохраняются кнопкой, автосохранение серверного черновика наряда остаётся прежним. Полный набор объектов появится только после получения полных чертежей. Система не объявляет неизвестную физическую готовность по отсутствующим записям.
