# Рабочие процессы координатора 0.14

Продолжение переработки Personal: пользователь поручил завершить оставшиеся функции и заменить крупные мобильные показатели маленькими иконками. Все пять показателей помещаются в одну строку на телефоне; число, title и доступное имя сохраняются. Нажатие по-прежнему открывает соответствующую выборку.

## Объёмы, дополнительные работы и люди

`WorkRow.actual` остаётся **заявленным** фактом. Независимые optional поля: `verifiedActual`, `verificationBasis`, `verifiedAt`, `verifiedBy`. Проверенный ноль — число 0, неизвестное/снятая проверка — null. Старые принятые наряды не получают проверенный объём автоматически.

Проверку сохраняет руководитель через `PUT /api/orders/:id/review`: сервер проверяет роль, доступ к наряду, ревизию, полный уникальный набор ID строк и основание каждого известного значения. Принятый наряд сначала возвращают в работу. Автор и время назначаются сервером, прежние значения остаются в снимках истории. Обычный save не позволяет бригадиру подменить проверку. При изменении заявленного факта проверка этой строки сбрасывается; приёмка и получение отчёта сами её не устанавливают. Несохранённая проверка блокирует приёмку и переход к другому наряду в реестре до сохранения/отмены.

`POST /api/orders/:id/additional` добавляет строку только в выданный наряд своей бригады, с проверкой ревизии и основания. Исходные строки и план сохраняются. Новая строка имеет собственные ID/автора/дату/основание, план null, факт вводится отдельно. Для сданного/принятого наряда требуется возврат. Допработа не наследует вымышленную 3D-геометрию. Обычный save не позволяет тихо добавить/поменять исходные строки.

Планирование возможно без модели: «Добавить работу без 3D-привязки». Потребность и геометрия у такой строки не определены; она не смешивается с другим ручным участком по пустому набору элементов.

`plannedPeople` и `reportedPeople` отдельно от списка `crew`: план трудовых единиц, заявленное количество и поимённый табель. Неизвестное число остаётся пустым; расхождение показывается, не исправляется автоматически. Новая выдача и перенос сбрасывают заявленное количество/проверки/время. Ночные часы остаются по фактическому табелю.

«Ход работ» показывает заявленный и проверенный факт и их остатки отдельно. Разные единицы/основания не складываются. Для проверки назначений используется известный проверенный объём, иначе прежний заявленный; неизвестные значения не подставляются нулём. Это оперативное планирование, а не автоматическая исполнительная приёмка конструкции.

Excel сохраняет прежние три листа и структуру. В примечаниях строк теперь есть независимый проверенный объём, основание, автор/дата и происхождение допработы; заявленный факт остаётся в прежней числовой колонке. В примечаниях табеля — количества трудовых единиц и точные состояния подписей. Бинарный шаблон не менялся.

## Бумажные подписи

Четыре состояния для выхода и окончания: `unchecked` / `present` / `missing` / `illegible` («Не проверено», «Есть», «Отсутствует», «Неразборчива»). Для отмеченного результата нужна настоящая фотография правильного наряда, бригады и этапа. Старые ссылки на фото трактуются как прежняя отметка «Есть»; отсутствие новых optional полей из старого клиента не стирает проверку. Явное снятие очищает ссылку.

Сохранён привычный чекбокс «подпись есть» и добавлены точный выбор состояния и применение результата выбранного листа к списку сотрудников. Для «Есть» необходимо заполненное время, как в прежней версии; остальные строки при массовой отметке не подтверждаются автоматически. Отсутствующая или неразборчивая подпись — отдельный результат проверки, а не подтверждение отсутствия работника. Часы не вычисляются из подписей. Итоги/история/сменная сводка различают эти состояния.

## Подрядчики, техника и путевые листы

Новые типы construction payload: `contractor`, `machine`, `waybill`, `request`, `proposal`. Они используют прежние таблицы записей/истории/файлов, optimistic revision и бригадную область доступа. Создание/изменение справочников и согласование выполняет руководитель; другие роли читают доступные записи. Это ручной процесс Personal, не подтверждение контрагентом в будущей Platform.

- Подрядчик: название, контакт, телефон, бригада, участок, активность, примечание.
- Техника: тип/название, государственный или инвентарный номер, собственник, бригада/участок, активность. Повтор того же номера отвергается.
- Путевой лист: номер, машина, бригада, дата/день/ночь, optional связь с нарядом той же смены, реальные даты/время начала и окончания, общие часы, строки работы и часов на нескольких участках, источник, оригинал и состояние.

Общие часы и часы по участкам **не приравниваются автоматически**: простои, переезды и пересечения ещё требуют точного образца. Для «Проверено» нужны оригинал, известные общие часы и заполненное распределение. Время окончания проверяется с календарной датой, включая ночь. Повтор одного номера для той же машины/даты/смены блокируется. Многоучастковый лист находится также через участки его распределения. Это универсальная карточка, а не утверждённый формат реального путевого листа.

## Предложения и заявки

Предложение работ: подрядчик, участок, бригада, дата/смена, работа, объём/единица, техника, источник/комментарий, состояния «Предложено», «Согласовано», «Отклонено». Из согласованного предложения формируется редактируемый черновик наряда с ID источника. Выдача проверяет совпадение участка, бригады, даты и смены с согласованным предложением. Аккаунт подрядчика не требуется; источник вводит координатор. При переносе в другую смену связь с прежним согласованием очищается.

Заявки на материалы/технику: черновик → согласовано → заказано/назначено → получено. Переходы проверяет сервер; обход согласования запрещён. Для исполнения нужен известный объём, для отмены — причина. Получение по заявке не создаёт вымышленный складской приход/расход: операция регистрируется отдельно с её основанием в «Материалах». Записи, изменения и файлы сохраняются; CSV выгружает видимую выборку и защищает текст от формульной интерпретации.

## Фото, видео и документы наряда

Document имеет optional `orderId`; сервер проверяет участок и бригаду связанного наряда. Руководитель может прикрепить исходный файл и источник прямо из наряда. Один файл на неизменяемую документную запись; для другого файла — новая запись/редакция. Документы доступны также в разделе объекта. Альбомы подписей сохраняют прежний отдельный защищённый механизм.

Поддержаны JPEG/PNG/PDF/XLSX/DOCX и видео MP4/WebM/MOV до 25 МБ. Видео не перекодируется и требует поддержки кодека браузером; при ошибке доступен оригинал. Хранение — закрытая SQLite, не публичная статика. Видео выдаётся с нужным MIME и защищённым одиночным HTTP Range; до чтения проверяются сеанс и область доступа. Оригиналы не заменяются обработанными кадрами, снимками или выдуманным распознаванием.

## Совместимость, проверки и границы

Project v1/v2, геометрические количества и SQLite schema2 не менялись. Browser archive v1 расширен optional полями. Старые файлы читаются. После появления новых видов construction-записей старый сервер 0.13 не является поддерживаемым откатом: он не знает новые payload kinds. Для следующего развёртывания переиспользовать БД и upgrade, не выполнять bootstrap/restore поверх новых данных.

Полная корпоративная Platform с цифровым подтверждением подрядчиками, внешними каналами доставки, кадровой/диспетчерской интеграцией и утверждёнными формами документов остаётся отдельным направлением. Этот выпуск покрывает ручные рабочие процессы координатора, не автоматизирует юридическое подписание, не вводит цены и не придумывает полный состав ещё не полученных чертежей.

Новые файлы: fieldOperations/FieldOperationsPanel, field-validation, orderReview/OrderReviewPanel, ManualWorkComposer, OrderMedia/constructionFiles и field-operations.css. Проверки: server/shift-operations.test.ts, дополнение workProgress.test.ts, integration/zz-operations.spec.ts. Тестовый WebM — синтетический рисунок из `integration/fixtures`, не исходное пользовательское видео. Для запуска тестов Python/FFmpeg не нужны. Все рабочие исходники, тестовые БД/снимки/инструменты и реквизиты остаются в исключённых каталогах; в Git только код и синтетический fixture. Фактические результаты запусков и выкладки — в PROJECT_STATE/HANDOFF.
