# Рабочие данные Ярославского направления

17.11.2026 по запросу пользователя заполнена действующая общая база, а не демонстрационная локальная модель. Код на момент заполнения — 0.14; исправления компоновки карты — 0.14.1. Исходный Excel и PDF остаются только в закрытом хранилище документов и исключённых локальных каталогах. Они не включаются в Git или публичные assets.

## Что добавлено

- Пять корневых объектов из столбца «Объект» листа «ОБЪЕМ»: Маленковская, Яуза, Ростокино, Лосиноостровская, Лось.
- 27 вложенных объектов: однозначно названные платформы, стройплощадки и участки; кассовый павильон и навес Маленковской связаны с существующими `kzh-pavilion`/`kzh-canopy`. Итого 32 node-записи.
- Девять карточек подрядчиков из Excel. В описаниях сохранены станции, на которых подрядчик встречается в исторических строках. Это справочник, не подтверждение выхода на текущую смену.
- Своя бригада ООО МТС. Имя области доступа «Наша бригада» сохранено для действующего входа бригадира. Неизвестные руководитель и состав не выдуманы.
- Оригинальный Excel и оригинальный PDF КЖ1.5 Маленковской в разделе «Документы». Файлы скачиваются через защищённый API. SHA256 сохранён в описании и метаданных вложения.

Всего 44 записи: 32 node, 9 contractor, 1 crew, 2 document. Импорт выполнен через авторизованный API с обычной историей/автором и предварительным backup; прямого редактирования SQLite не было. Существующие записи не перезаписывались. Повторный план перед добавлением PDF нашёл все 43 прежние записи; повтор после завершения должен пропустить все 44.

## Границы исходных данных

В Excel 4961 строка объёмов за 02.09–16.11.2026. Исторические наряды, ФИО/часы и факты не превращены в новые выданные/принятые наряды. Пользователю отдельно задан вопрос о переносе истории; до ответа импортированы справочники и оригинал. Поимённый выход сегодня и назначения техники вводятся по текущей смене.

197 строк содержат неоднозначные обозначения участков: другие названия станций внутри текущего объекта, составные номера «1.2»/«1,2,3», прочерк. По ним не создавались новые геометрические объекты и произвольные связи. Строки сохранены в исходном Excel; закрытый отчёт разбора — `.deploy/workspace-import-ambiguities.json`.

Маленковская — текущая станция пользователя; кнопка модели открывает существующий навес, через структуру доступны обе сборки. Это только часть КЖ станции. Остальные станции не получают чужую модель или придуманную геометрию. Общие объёмы станции, прогресс и текущая численность из геометрии одной сборки не выводятся.

## Положение на карте

Маркеры — ориентиры станций, а не геодезические координаты строительных конструкций или границы работ. Координаты проверены 17.11.2026 и источник указан в каждой карточке:

- [Маленковская](https://ru.wikipedia.org/wiki/Маленковская_(платформа)), 55°48′51″ / 37°39′46″.
- [Яуза](https://ru.wikipedia.org/wiki/Яуза_(платформа)), 55°49′44″ / 37°40′16″.
- [Ростокино Ярославского направления](https://ru.wikipedia.org/wiki/Ростокино_(платформа,_Ярославское_направление_МЖД)), 55°50′38″ / 37°40′14″. Не станция МЦК.
- [Лосиноостровская](https://www.tutu.ru/poezda/station/map/2001125/), 55.862804 / 37.682995.
- [Лось](https://ru.wikipedia.org/wiki/Лось_(платформа)), 55°52′47″ / 37°42′37″.

Карта вписывает точки без переходной анимации масштабирования SVG и повторно вписывает их при изменении размеров окна. Длинное описание источников свёрнуто в раскрываемый блок. Подложка OSM требует сети; в автоматических проверках тайлы намеренно заблокированы, маркеры/список и операции продолжают работать.

## Проверка и передача

### Открытие станции с 0.14.2

Строка в списке, круглый маркер и подпись станции сразу открывают её рабочее пространство. Раньше они только меняли выбранную карточку; для первой станции, уже выбранной по умолчанию, клик выглядел бездействующим, а отдельная кнопка открытия находилась ниже на телефоне. Теперь отдельный повторный шаг не нужен. Подписи карты — настоящие кнопки с доступным именем, поддерживают клавиатуру и касание. Серверный тест проверяет открытие уже выбранного первого объекта и реальные tap по строке/подписи/маркеру.

Закрытые служебные файлы `.deploy/prepare-workspace.py`, `workspace-manifest.json`, `import-workspace.mjs` и результаты не коммитятся: это одноразовая подготовка конкретного источника, а не готовый универсальный импорт произвольного Excel. `workspace-data-check.mjs` проверяет маркеры, записи, модель, хеш оригинала и отсутствие переполнения. Перед повторным применением читать актуальные records: не перезаписывать изменения пользователя.

Фактические итоги проверок, backup и опубликованного release — в верхних разделах PROJECT_STATE.md/HANDOFF.md. Не удалять заполненную production-базу и не выполнять bootstrap.
