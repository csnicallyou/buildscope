# BuildScope — спецификация связанных экранов (UX → визуальные макеты)

**Статус:** проектное решение, не утверждённые визуальные макеты. Основание: [UX_INFORMATION_ARCHITECTURE.md](./UX_INFORMATION_ARCHITECTURE.md), [WORK_PROGRESS_MODEL.md](./WORK_PROGRESS_MODEL.md). Один новый продукт. Реальные цифры и фамилии ниже — **демонстрационные**, не данные станции.

## 1. Общие правила интерфейса

**Контекст:** project_id → site_id → shift_id (необязателен) → work_order_id/report_id/element_id. Контекст сохраняется при переходе между экранами, фильтры и сортировка восстанавливаются при возвращении.

**Рабочая оболочка:** узкая боковая навигация, строка поиска, переключатель станции, период/смена, уведомления. На широком экране допускается таблица + правая инспекторная панель; на телефоне инспектор открывается отдельно.

**Визуальная иерархия:** данные и действия важнее декоративных эффектов. Плотные таблицы, явные единицы измерения, чёткие статусы, контрастная типографика, аккуратные объёмные панели. Цвет не единственный носитель статуса; не использовать «красивые» графики вместо точных чисел.

**Ключевой принцип:** основной показатель **план / установленный факт / остаток**. «Заявлено подрядчиком» — дополнительная колонка или раскрываемый источник, а не обязательная стадия согласования.

## 2. Экран A — контроль подрядчиков за смену

**Цель:** за минуту понять, от кого есть отчёт, где не внесён факт, какие расхождения требуют внимания.

- Верх: станция, смена (например, 18.11 20:00 — 19.11 08:00), фильтр организации, поиск, «Новый наряд», «Загрузить отчёт».
- Сводка: подрядчиков в смене; ожидается отчётов; получено; без установленного факта; строки с расхождениями. Показатели вычисляются из нарядов и отчётов, не из ручных статусов.
- Основная таблица: организация, объект/зона, наряды, время получения, состояние отчёта, строк с установленным фактом / всего, отклонения, ответственное лицо, действие.
- Состояния: «не ожидался», «ожидается», «получен», «в обработке», «факт внесён», «есть расхождения». «Не получен» не означает «не работали».
- Выбор строки открывает инспектор с нарядами и документами. «Проверить» открывает экран C с сохранением станции и смены.
- Собственная бригада ООО «МТС» отображается как отдельная рабочая группа, не теряется среди подрядчиков.

**Пустые/ошибочные состояния:** нет нарядов; нет отчётов; неизвестна организация; дублирующий документ; нет прав; связь недоступна. Для каждого есть понятное действие без выдуманных данных.

## 3. Экран B — журнал нарядов

**Цель:** планировать, выпускать и искать наряды, сравнивать план смены и её факт, переходить к общему прогрессу.

- Верх: станция, период, смена, подрядчик/бригада, статус выдачи, тип работ, поиск, «Создать наряд», «Экспорт».
- Таблица по нарядам с раскрытием строк: №, редакция, смена, организация, зона/конструкция, вид работ, план смены, факт смены, единица, общий план, накопительный факт, остаток, источник, состояние.
- Числа по разным единицам не суммируются в один итог. Для неизвестного факта показывать «— / нет данных», для подтверждённого нуля «0».
- Открытие строки показывает справа связанную конструкцию, историю редакций, исходные документы, исполнителей и технику (если есть).
- Выпуск наряда сохраняет редакцию; изменения после выдачи — новая редакция, не незаметная правка оригинала.
- Внеплановые работы показываются отдельно и могут быть привязаны к общей цели позднее, но не скрываются.
- Массовые операции: фильтрация, экспорт выбранных, копирование плана на следующую смену **как новый черновик**, а не как выполненный факт.

## 4. Экран C — проверка полученного отчёта

**Цель:** быстро и точно перенести факт из бумаги/Excel или проверить цифровой отчёт.

**Desktop:** левая панель (35–45%) — оригинал документа, страницы, масштаб, поворот; правая — таблица строк наряда и отчёта; нижняя панель — часы, люди, подписи начала/конца, техника, вложения, примечания.

**Таблица:** вид работы, объект/элемент/группа, единица, план смены, заявлено (если известно), **факт (редактируется координатором)**, разница, источник строки, комментарий. OCR предлагает распознанные значения, но **никогда не записывает их как установленный факт без подтверждения**.

**Основные действия:** «Сохранить черновик», «Зафиксировать факт», «Добавить внеплановую работу», «Показать источник», «История изменений», «Следующий отчёт». «Зафиксировать факт» валидирует единицу, область и права, создаёт редакцию и обновляет накопительный прогресс.

**Различия:** если подрядчик сообщил 12 м³, а координатор фиксирует 10 м³, в основной журнал идёт 10 м³, исходные 12 сохраняются. Отсутствие подписи отображается как неизвестно/отсутствует/неразборчиво, а не подставляется автоматически. Смена через полночь не разбивается.

**Защита:** выход с несохранёнными изменениями требует подтверждения; конфликт редактирования предлагает сравнение версий; дубли импорта — сопоставление, а не автоматическое добавление.

## 5. Связь A ↔ B ↔ C

1. Из A выбрать подрядчика → B показывает наряды этого подрядчика на той же смене.
2. Из B выбрать наряд → C открывает соответствующий отчёт или состояние «ожидается» с возможностью загрузки.
3. После фиксации факта в C → B обновляет факт смены, накопительный факт и остаток; A обновляет состояние отчёта.
4. Возврат из C → B/A сохраняет фильтры и позицию в списке.
5. Из любой строки открыть конструкцию → рабочее пространство объекта с выделенным элементом; при отсутствии 3D открывается таблица/дерево.

## 6. Мобильное поведение

- A: компактные строки организаций с раскрытием состояния и действия.
- B: не пытаться втиснуть 12 колонок; карточки нарядов с первыми полями «смена, работа, план, факт», расширение по нажатию.
- C: переключатель «Оригинал / Ввод факта», закреплённая кнопка сохранения, явное указание выбранной строки. Возможность увеличивать документ жестами.
- Доступ к истории и источникам остаётся, но вторичные панели открываются отдельно.

## 7. Сценарии для проверки макетов

1. Утром пришли 3 отчёта, один отсутствует → A различает состояния.
2. По строке план 12 м³, заявлено 12, установлен факт 10 → C сохраняет 10, B показывает остаток по общему плану.
3. Подрядчик прислал дополнительную работу без строки наряда → C позволяет добавить и связать с объектом.
4. У своей бригады неизвестны фамилии на момент выдачи → B выпускает наряд; C добавляет людей и подписи позже.
5. Исправление вчерашнего факта 5 → 4 → итог накопительного прогресса уменьшается на 1, история сохранена.
6. Фундамент без геометрии → из B/C открывается карточка в дереве/таблице.
7. Нет сети во время заполнения → интерфейс не обещает отправку; сохраняет данные только если отдельно реализован локальный черновик.
8. Подрядчик с ограниченными правами не видит отчёты чужих организаций и не может зафиксировать координаторский факт.

## 8. Критерии готовности к визуальному макетированию

Структура и переходы определены. На следующем шаге создать **связанные визуальные макеты** главной, пространства станции и экранов A/B/C в единой стилистике; показать desktop и основные mobile-состояния. Никаких изменений в коде приложения до согласования макетов и техплана.
