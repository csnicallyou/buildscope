# Архитектура

## Инженерное ядро

`src/model.ts`: совместимое чтение Project v1/v2, Zod-валидация, AABB union, количества элементов, геометрический/исходный CSV, параметрическое демо. `src/engineering.ts`: схемы новых геометрий, происхождение, ведомости, количественные формулы и валидация. React/Three.js не используются в ядре.

V1 — объединение AABB. Границы частей образуют ячейки; занятая ячейка учитывается один раз, площадь считается по открытым граням. V2 добавляет:

- Экструзию простого невыпуклого профиля: площадь контура по формуле Гаусса, объём = площадь × глубина, поверхность = 2 × площадь + периметр × глубина.
- Замкнутое треугольное тело: ориентированные тетраэдры для объёма, площади треугольников для поверхности. Проверяются индексы, замкнутость и согласованность ориентации рёбер.
- Стержень по ломаной: номинальные длина/объём/поверхность. В каталоге это схема, исключённая из количества материалов.

Один элемент содержит либо объединение parts, либо shape. Не складывать пересекающиеся части разных видов геометрии без геометрического ядра. Межэлементные пересечения не вычитаются.

## Источники и реконструкция

`src/kzh.ts`: предметный генератор двух сборок, варианты отметок, источники и противоречия. `src/data/kzh-layout.json`: раскладка 205 ФБС / 58 ФЛ, извлечённая из векторных разрезов конкретного PDF. `scripts/extract_kzh_layout.py`: воспроизводимое извлечение с калибровкой по высоте 580 мм, удалением одинаковых подписей и проверкой количеств. Это не общий PDF/BIM parser.

`src/data/kzh-schedules.ts`: исходные позиции армирования с неизменёнными количествами, длинами и округлёнными массами. `src/details.ts`: 22 схематических образца гнутых деталей. `npm run export:projects` валидирует и записывает JSON/два CSV для каждого представления.

representation отделяет тела по размерам, номинальные изделия, схемы и огибающие. Последние два исключаются из totals/геометрического CSV; reportedVolume и document.materials остаются независимыми данными источника. Схема основных сеток не заменяет полную изготовительную модель армирования.

## Состояние, рендер и UI

`src/store.ts`: проект отдельно от временного положения, скрытия, изоляции, проекций, замеров и режимов. `displayPosition` не меняет исходный проект.

`src/geometry.ts`: единый перевод геометрии в Three.js для viewer и GLB. Экструзии — встроенный ExtrudeGeometry, серийные объёмы — треугольные тела, стержни объединяются в меш для каждого элемента. `src/Viewer.tsx`: камеры, выбор, clipping planes, сетки и стержни. Материал принудительно обновляется при изменении параметров; без этого ранее оставался opaque shader. Подписи осей — WebGL sprites, не DOM Html: быстрое переключение DOM roots приводило к removeChild в React 19. Замер отображается обычным React-слоем вне Canvas.

`src/App.tsx`, `src/DocumentPanels.tsx`, style.css: рабочее место, переключение сборок, дерево, свойства, исходные ведомости, гнутые детали, реестр листов и локальный PDF iframe через object URL. PDF не сохраняется в JSON и не передаётся на сервер.

`src/importers.ts`: отдельный DXF DrawingImporter, результат — 2D сегменты с предупреждениями. `src/export.ts`: GLB по исходным координатам и метаданным, без временных сдвигов.

## Ограничения

Метры, Y вверх; две сборки не имеют общей привязки. Ноль 146,35 относится к сооружениям; у условного каталога абсолютная отметка null. Нет BRep/универсального CSG/IFC/произвольной реконструкции PDF, поддержки отсутствующего тела и статусов отдельных числовых полей. Python нужен только для повторного извлечения PDF, не для приложения. Лимиты расчёта AABB: 64 части, 250 тыс. ячеек на элемент, 2 млн. на проект, 10 тыс. элементов. Схемы арматуры ограничены 4000 путями на элемент.

В 0.3 objects.ts строит иерархию из parentId и временные компоненты отдельного вида, считает материальные строки с явными неизвестными. ObjectInspector.tsx разделяет сводку объекта, тело и схему стали. store.openedObject меняет только область просмотра, выбор, видимость и смещения; source Project не мутирует. Viewer использует те же sceneItems/visibleItems для мешей, рамки камеры и счётчика.

В 0.4 calculator.ts канонизирует выбранные ID через modelObjects, разворачивает уникальные исходные элементы и объединяет materialAmounts по материалу/единице, сохраняя основания и число неизвестных позиций. SelectionCalculator.tsx отображает итог и экспортирует отдельный CSV. store.calculatorOpen/calculatedObjects — временные состояния: select в этом режиме переключает корень объекта; load очищает набор, визуальные операции не меняют его. Viewer подсвечивает все тела отмеченных сборок.
